# Мобильный UX 2.0 — интеграция в настоящую игру

Рабочая ветка: `multiplayer`. Основная ветка, игровой движок, Worker, протокол и правила магии не изменены.

## Что перенесено

- Общие `MobileFan`, `MobileCardFace`, `MobileSheet` выделены из одобренного прототипа. Прототип использует те же компоненты; демонстрационные карты и контроллер в production JS не входят.
- `MobileHand`: до шести карт — веер с отдельными неперекрывающимися зонами касания; 7–15 — раскрываемый веер; больше 15 — компактная стопка и обзор. Обзор показывает все собственные карты, включая заблокированные, и прокручивается вертикально.
- Выбранная карта вынесена в отдельную строку между столом и действиями. Повторное касание снимает выбор; несколько карт одного ранга сохраняют групповое выделение. Озвучка вызывается прежним обработчиком через `speech.ts`, настройка звука действует.
- `MobileBattle`: до шести пар в трёх колонках, защита смещена на 15 × 18 px. Невидимая кнопка каждой пары ограничена её собственной ячейкой. Доступные цели подсвечиваются. На телефоне защита требует выбора цели и кнопки «Защитить». Нажатие на пару без доступной защиты открывает крупный просмотр с озвучкой и переводом.
- Предпросмотр занимает собственную строку; на коротком экране стол прокручивается независимо. Предпросмотр длинного слова также может прокручиваться, не перекрывая действия.
- HUD высотой 64 px без большого веера соперника. Игровые действия между столом и рукой; компактный доступ к прежней магической галерее в той же строке. В задании сначала вопрос и ответы, затем иллюстрация и описание.
- Закрытая рука использует только непрозрачные ссылки, без создания лиц карт, слов, мастей или TTS. Слепой выбор на телефоне требует подтверждения «Атаковать». Настольный сценарий сохранён.
- Сохранены `TableCard`, `BoardImpact`, существующие анимационные события и слой перелётов; мобильные поступления используют прежние задержки. Все изображения — прежние WebP/SVG.

## Результаты проверок

- TypeScript (`npm run build` сначала выполняет `tsc --noEmit`) и production-сборка проходят. В сборке есть мобильные компоненты обоих режимов и нет демонстрационных карт прототипа.
- 68 общих тестов прошли, включая отдельную проверку отсутствия лица/масти/слова/TTS в слепом предпросмотре.
- 30 тестов Worker прошли: настоящие WebSocket, все семь эффектов, оба направления учебных заданий, приватность, обновление состояния, восстановление комнаты и задания, защита авторизации. Для некоторых серверных тестов используются их прежние детерминированные внутренние раздачи; они не используются при проверках приложения ниже.
- Playwright-прототип: 320, 360, 390, 430 и 844 × 390, свайпы, TTS, все шесть зон касания, обзор 12/20 карт, все шесть пар.
- Настоящее приложение: production `dist`, локальный Miniflare с текущим исходным Worker и двумя отдельными браузерными контекстами. `runtimeModules()` вызван без инъекции раздач или серверных снимков. Создание, вход, начало и все ходы выполняются через UI. Снимки сервера только наблюдаются для выбора разрешённого хода и сверки результата.
- В сетевых партиях проверены атака, защита с отдельным подтверждением цели, подкидывание, частично отбитый стол, шесть атак, взятие, очистка и следующий раунд. Большие руки получены обычным взятием карт; магия — обычным добором.
- Проверены 320 × 700, 360 × 780, 390 × 844, 430 × 932 и настольная 1440 × 900. Мобильный HUD — 64 px, строка действий — 54 px, кнопки — не меньше 44 px. Стол — три колонки; низ руки находится внутри viewport. Веер соперника и настольный HUD отсутствуют на телефоне. Зоны касания шести карт не пересекаются и имеют ширину не меньше 44 px.
- Настоящая одиночная партия с действующим ботом также проверена на четырёх портретных ширинах: атака, защита и несколько карт на столе. Только на время последовательного снятия размеров/скриншотов Playwright приостанавливает часы страницы; состояния и ходы не подменяются, после снимков бот продолжает играть.
- Обновление страницы, повторное открытие в новой вкладке того же браузерного контекста и offline/online сохраняют `PlayerView`. Открытое магическое задание восстанавливается без новой раздачи. В дополнительном настоящем прогоне проверена слепая атака после «Обезьяньей проделки»: обзор закрытой руки, рубашка в предпросмотре, отсутствие слова и подтверждённый ход. Снимок — `network-blind-preview.png`.
- В настоящей сетевой партии проверены выбор/повторное касание, прежний TTS (звуковой вывод браузера заменён счётчиком только в тесте), выключение озвучки настройкой и свайп, который не выбирает карту и не меняет серверную revision.

Компьютерные проверки не заменяют проверку реального Android: адресная строка, переключение приложений, системный голос и производительность устройства требуют отдельного прохода после публикации.

## Повторение локальной проверки

Нужен Node 22+, установленный Playwright либо путь к существующему пакету в `PLAYWRIGHT_MODULE`, Chrome либо браузер Playwright. Новые зависимости в проект не добавлялись.

1. `npm test`, `npm --prefix worker test`, `npm run build`.
2. В отдельном терминале: `node scripts/start-mobile-check-worker.mjs` (только localhost:8787; берёт текущий Worker без тестовой раздачи).
3. В другом терминале: `npx vite preview --host 127.0.0.1 --port 4176`. Сборке для этого локального прогона нужен `VITE_ROOM_API_URL=http://127.0.0.1:8787`.
4. `node scripts/check-mobile-integration.mjs`; можно отдельно указать `CHECK_MODE=network` или `CHECK_MODE=solo`. Проверка создаёт только локальную комнату, публичные адреса запрещены. Раздача случайная; дополнительный `CHECK_GOAL=blind` требует, чтобы естественно выпавшая «Обезьянья проделка» дошла до слепой атаки.
5. `node scripts/check-mobile-build.mjs --git-head` после коммита проверяет, что новые файлы действительно входят в HEAD.

## Проверка на Android после публикации

Открыть тестовый Pages-сайт в Chrome, обновить страницу. Создать комнату, второму игроку открыть приглашение на другом устройстве. Проверить выбор/снятие карты, защиту разных целей, шесть атак с прокруткой стола, обзор большой руки и последнюю карту, магическую галерею/задание. Свернуть браузер и вернуть, отключить и включить интернет, открыть ту же ссылку повторно. Для другого браузера использовать персональный код восстановления.

Публиковать только ветку `multiplayer` для тестового `korean-card-game-multiplayer.pages.dev`. `main` не изменять; Worker не публиковать. Сборка Pages: `npm run build`, каталог `dist`; использовать существующую тестовую настройку `VITE_ROOM_API_URL`, не localhost.

### Особенность запуска тестов в этой среде Windows

Обычный `npm test` здесь останавливается внутри загрузчика `tsx`: `uv_os_get_passwd returned ENOMEM`. Ошибка возникает до выполнения тестов. Исходные тесты проверены альтернативным запуском: TypeScript транспилирован в одноразовый каталог `.wrangler/test-build`, затем выполнен штатным `node --test`; все 68 прошли. После `npm --prefix worker test` этот каталог уже содержит скомпилированные общие тесты. Повторить их в PowerShell можно так:

```powershell
$tests = Get-ChildItem -LiteralPath worker/.wrangler/test-build/src -Filter *.test.js | Select-Object -ExpandProperty FullName
node --test $tests
```

Настройку `npm test` и зависимости ради ограничения среды не меняли.
