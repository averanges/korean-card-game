# Восстановление доступа к сетевой комнате

## Причина ошибки

`recoverySecret` и ключ повторного входа `joinKey` сохранялись только в `sessionStorage`. Это хранилище относится к вкладке и может исчезнуть после её закрытия. Сервер при этом правильно сохраняет оба места, поэтому повторная попытка присоединиться с новым ключом получает `room_full`. Имя не является доказательством владения местом.

## Новый механизм хранения

Модуль `src/rooms/credentials.ts` сохраняет только `{ roomId, seat, recoverySecret }` в `localStorage` по ключу `hangul-room:ID`. Хранилище автоматически изолировано Origin браузером; ID отделяет комнаты. Приглашение, снимок партии, чужие карты и задания в нём не сохраняются.

Ключи повторного входа сохраняются отдельно как `hangul-join:ID`. Повтор запроса с тем же ключом сохраняет прежнюю серверную идемпотентность. Ключ создания комнаты остаётся под отдельным ключом `hangul-join:new`.

Совместимость со старыми вкладками:

- При открытии комнаты сначала читается корректная запись текущей `sessionStorage`, затем постоянная запись. Это сохраняет место прежней вкладки даже при разных местах в нескольких вкладках одного браузера.
- Найденные данные проверяются по формату и ID комнаты, лишние поля отбрасываются; запись переносится в постоянное хранилище. `joinKey` переносится аналогично.
- Запись в `sessionStorage` также сохраняется для совместимости. Если постоянное хранилище недоступно, используется сессия, затем память текущей страницы. Пользователь получает сообщение о необходимости сохранить персональный код; подключение не блокируется уже после выделения места сервером.
- Неверный секрет удаляется только после явного серверного отказа авторизации. Потеря сети и тайм-аут авторизации не считаются доказательством недействительности секрета. Удаление не стирает более новую запись другой вкладки.

При открытии `/room/ID` сохранённые данные автоматически используются для обычной авторизации WebSocket. Пока идёт восстановление, форма нового имени не показывается. Сервер присылает текущую проекцию игрока; новая раздача не создаётся.

## Персональный код

В лобби и по кнопке «Код восстановления» во время партии можно показать и скопировать свой код. По умолчанию он скрыт. Формат `HD1.<ID комнаты>.<существующий секрет>` не содержит номера места и не является URL.

На другом устройстве нужно открыть обычную ссылку этой комнаты и в разделе «Вернуться в игру» ввести персональный код. Новый `POST /api/rooms/ID/recover` получает секрет в JSON-теле, проверяет его существующей серверной `authenticate` и возвращает только данные авторизованного места. Само место определяет сервер по хешу секрета. Проверка не меняет партию, присутствие или версию комнаты и не создаёт игрока.

После проверки клиент сохраняет данные в своём браузере и открывает обычный авторизованный WebSocket. Актуальные карты, стол, эффекты и незавершённое задание восстанавливаются из снимка сервера. Секрет не передаётся сопернику и не добавляется в ссылку-приглашение или логи.

Если сервер сообщает, что комната заполнена, форма повторного ввода имени убирается. Вместо неё предлагается код либо исходный браузер. По имени, ссылке или выбранному номеру места восстановиться нельзя.

Персональный код нужно сохранить, пока доступ к месту ещё есть. Если уже потеряны и секрет, и ключ повторного входа, а код ранее не сохранён, безопасно восстановить старое место по имени невозможно. Ограничение срока жизни комнаты остаётся прежним; код не возрождает истёкшую комнату.

## Возврат соединения и безопасность

- Сохраняются heartbeat и ограниченные повторы соединения; возврат сети и видимости страницы запрашивает свежий снимок либо переподключает устаревший сокет.
- `pagehide` освобождает соединение и его таймеры, `pageshow` восстанавливает его. Поздние события прежнего сокета игнорируются.
- Тайм-аут первой авторизации допускает повтор, явный отказ — останавливает его.
- Сохраняется серверная замена прежнего соединения кодом `4009`. Вытесненная вкладка не подключается автоматически обратно ни по таймеру, ни после событий сети/видимости. Явное нажатие «Подключиться снова» в партии остаётся осознанным действием пользователя.
- Новый HTTP-маршрут использует прежнюю проверку Origin, ограничение тела 2048 байт, строгий список полей и `Cache-Control: no-store`. В JSON нельзя подставить имя или место. Модель хешей секретов, ограничения WebSocket и правила истечения комнаты сохранены.
- Данные разных браузеров, приватных окон и встроенных браузеров мессенджеров не объединяются. Для перехода между ними предусмотрен персональный код.

## Проверки

Успешно выполнены:

- 55 тестов общего кода, одиночного режима и клиентского представления, включая 5 новых тестов хранения и жизненного цикла соединения.
- 28 серверных тестов, включая новый интеграционный сценарий в настоящем Miniflare/workerd: занятая комната, неправильный/чужой секрет, попытки войти по имени/приглашению, проверка кода без изменения состояния, замена соединения, сохранение той же партии и того же магического задания, отсутствие секретов у соперника, лимиты сообщений и неавторизованных соединений.
- TypeScript frontend и Worker.
- Production-сборка `npm run build`.

Тесты хранения моделируют пустую новую вкладку при сохранённой постоянной записи и перенос прежней сессии. Тесты соединения моделируют обновление/повторное открытие, потерю сети, возврат видимости, `pagehide/pageshow`, поздний пакет старого сокета и остановку вытесненной вкладки. Это не заменяет проверку реального мобильного браузера.

## Ручной прогон на компьютере и телефоне

1. Войти двумя игроками, сохранить код каждого. Открыть магический вопрос на одном устройстве, обновить страницу: должны восстановиться то же место, рука, стол и четыре варианта.
2. Закрыть вкладку телефона и открыть прежнюю ссылку в том же браузере. Повторить после полного перезапуска браузера. Форма нового имени не должна появляться при сохранённом хранилище.
3. Отключить интернет, включить обратно; свернуть игру и вернуть её из фона. Убедиться, что приходит актуальный стол без новой раздачи и повторного задания.
4. Открыть приглашение в другом браузере без кода. Попытка нового входа в заполненную комнату должна показать объяснение и раздел восстановления вместо повторения формы имени.
5. Ввести персональный код этого игрока. Должны вернуться его карты и вопрос; прежняя вкладка должна остановиться с сообщением о замене. Возврат старой вкладки из фона не должен вытеснить новую автоматически.
6. Проверить неправильный код, имя другого игрока и код другой комнаты: доступа быть не должно. Продолжить обычную и магическую партию обоими игроками.

Эти реальные мобильные сценарии в среде Codex не выполнялись. Изменения подготовлены локально в ветке `multiplayer`; push, merge и deploy не выполнялись. Для использования нового ручного восстановления понадобятся обновления и frontend, и Worker; старый WebSocket-протокол авторизации совместим.
