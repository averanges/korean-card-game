# Этап 6 — учебные замки и аудирование

Дата: 20 октября 2026. Ветка: `multiplayer`. Push, merge и deploy не выполнялись. Изменения этапа оставлены для проверки, без нового коммита.

## Результат

Учебная механика подключена к настоящим одиночным и сетевым партиям. Начальные шесть карт открыты. При последующем обычном доборе каждая карта независимо получает учебный замок с вероятностью 40%. Это прежняя физическая карта из 36: она учитывается в руке и условиях завершения партии, но не может участвовать в атаке, защите, подкидывании или обмене, пока закрыта.

Учебная разблокировка не завершает ход и доступна при ожидании соперника. Бот автоматически открывает свои карты без учебной задержки; проверка награды у него такая же, как у человека. Временная блокировка Призрачного вора остаётся отдельным состоянием.

## Состояния, команды и вероятности

`src/learning.ts` содержит общий чистый редьюсер и `learningSettings`: `LOCK_CHANCE = .40`, `MAGIC_REWARD_CHANCE = .25`, `LISTENING_ATTEMPTS = 3`.

Для физической карты хранятся непрозрачная ссылка, признак замка, ошибки, результат первой попытки, факт успешного открытия и отметка уже выполненной проверки награды. Для задания — идентификатор, варианты ответа, выбранный ответ, фаза `question / feedback / success`, признак закрытого окна. Повторная блокировка возвращённой в колоду карты не обнуляет отметку награды.

Новые сетевые команды: `begin_unlock(cardRef)`, `answer_unlock(challengeId, option)`, `continue_unlock(challengeId)`, `close_unlock(challengeId)`. Они проходят существующую авторизацию, проверку принадлежности карты, версии состояния и повторов запросов. Внутренний `unlock_bot` недоступен через сетевой протокол.

Аудирование использует существующие команды активации магии. Сессия дополнена числом ошибок, последним неправильным ответом и сохраняемыми попытками для каждой магической карты. Закрытая после ошибки сессия при повторном открытии возобновляется.

## Скрытая информация и проверка ответов

В сетевой проекции запечатанная карта владельца содержит только `{ref, ko}`. Её физический ID, ранг, масть и перевод не передаются; ссылка генерируется независимо от ID. Соперник получает только допустимые счётчики. События добора и истечения блокировки также фильтруются. Слепая атака не получает лиц обычных карт даже через событие разблокировки.

Сервер формирует вопросы по словарю текущей партии и сам проверяет выбранный индекс. Для чтения количество ошибок не ограничено: неверный вариант красный, правильный зелёный, затем варианты перемешиваются. Открывается конкретная физическая карта, без нового добора.

Для магии используется корейская озвучка и четыре русских варианта. Первые две ошибки не раскрывают правильный ответ; третья сжигает карту и показывает слово с переводом. Правильный ответ на любой из трёх попыток запускает прежний магический эффект. Повторное прослушивание не расходует попытки. Отмена до первого ответа свободная; после ошибок не сбрасывает счётчик.

Озвучка использует общий `src/speech.ts`, `speechSynthesis`, корейский голос и скорость .88. При отсутствии API/голоса, исключении или отсутствии старта воспроизведения ответы недоступны, карту можно сохранить закрытием окна. Платные сервисы не добавлялись.

**Техническое ограничение:** браузерный TTS требует передать корейскую строку владельцу задания. Она скрыта в интерфейсе и доступных подписях, но доступна владельцу через инструменты разработчика. Это не криптографическая защита учебного ответа. Для неё потребовалось бы отдельное серверное аудио. Скрытые ранги, масти и руки соперника этим способом не передаются.

## Магические награды

Старое случайное выпадение магии при доборе отключено. При первом успешном открытии физической карты один раз выполняется независимая проверка 25%; отметка сохраняется и при отсутствии бонуса. Поэтому переоткрытие или переподключение не даёт повторной проверки.

Награда берётся из существующего конечного пула 11 магических карт. В `src/magicDrops.ts` веса выбора: легендарная .35, обычная 1 на каждый оставшийся экземпляр. Исчерпание пула не мешает разблокировке. Магия остаётся дополнительной рукой и не замещает обычную карту. Жёсткого лимита трёх наград нет.

## Сохранение и восстановление

В сети состояние замков, вопросов, ошибок, наград и слушания сохраняется атомарно вместе с партией в Durable Object. Повторное подключение получает актуальную безопасную проекцию. Существующие секреты восстановления, политика замены WebSocket и серверные ограничения не изменены.

Старые комнаты без учебного состояния мигрируют без новой раздачи: текущие карты открыты, новые замки возможны при следующих доборах. Старое незавершённое текстовое магическое задание переводится в аудирование. Уже существующие магические карты не удаляются.

Для одиночной игры добавлено локальное сохранение `hangul-solo:v1:<guestPlayerId>`: партия, учебные вопросы, ошибки, награды и незавершённая магия. Запись результата происходит до обновления интерфейса; быстрый refresh не повторяет награду. При восстановлении не воспроизводятся события получения награды. При недоступном хранилище показывается сообщение. Очистка данных браузера удаляет одиночное сохранение; между браузерами оно не переносится. Сетевые секреты в это сохранение не входят.

## Представление и анимации

Используется чистый `public/assets/sealed-card.webp` (~95 КиБ): бордовый фон, золотая рамка, красные цепи и замок. Корейское слово выводится динамически; ранга, масти и перевода на закрытом лице нет. Компонент общий для настольной руки, мобильного веера и расширенного обзора. Переводы открытых карт по умолчанию включены; сохранённое явное предпочтение пользователя не перезаписывается.

При доборе закрытая карта получает короткую красную подсветку. Успешное открытие запускает представление конкретной карты примерно на 1 секунду. Награда стартует от её DOM-позиции, выходит в центр с русским названием, затем приходит в магическую руку: обычная — 1.8 секунды, легендарная — 2.8 секунды. Последовательность не задерживает применение правил. Изменение ширины или высоты окна очищает временные визуальные элементы; уменьшение движения отключает длинные перелёты. Награда привязана к исходному `sourceRef`, включая разблокировку при слепой атаке.

## Локальный запуск и будущая публикация

Из корня проекта:

```powershell
npm run build
npm test
npm --prefix worker run check
npm --prefix worker test
node scripts/check-learning-build.mjs
node scripts/check-mobile-build.mjs
```

В среде Codex стандартный запуск `tsx` ранее выдавал системный `uv_os_get_passwd ENOMEM`. Здесь 81 исходный тест был запущен через локальный вспомогательный транспилятор `work/check-rooms.mjs solo` и стандартный Node test runner; серверные 35 — штатным `worker/scripts/test.mjs`. Вспомогательная папка `work` игнорируется Git. Это ограничение окружения, а не причина считать неудачный запуск успешным.

Для ручной проверки: настроить игнорируемый `.env.local` на адрес локального Worker, запустить `npm --prefix worker run dev` и `npm run dev`. Создать комнату в двух браузерных профилях, доиграть первый раунд, открыть замок, ошибиться, перезагрузить страницу, завершить вопрос; получить награду и проверить три попытки аудирования. Повторить в `/singleplayer`. Проверить реальный корейский голос, поворот телефона и настройку уменьшения движения.

Автоматические UI-проверки `scripts/check-learning-ui.mjs` и `scripts/check-learning-solo.mjs` рассчитаны на production preview `127.0.0.1:4176` и Worker `127.0.0.1:8787`; путь к Playwright задаётся через `PLAYWRIGHT_MODULE`, к Chrome — `CHECK_BROWSER`. Локальный проверочный Worker запускается `scripts/start-mobile-check-worker.mjs` после серверных тестов и использует настоящий код и сохранение Miniflare.

Публикация требует отдельного разрешения: проверить diff в `multiplayer`, создать коммит со всеми новыми файлами/ассетом, затем согласованно обновить тестовый Worker и тестовые Pages `korean-card-game-multiplayer.pages.dev`. Pages: команда `npm run build`, каталог `dist`. Новых серверных секретов, зависимостей или namespace не требуется. Старые вкладки следует обновить: прежний JS не умеет показывать новый учебный протокол. Основную `main` и production-публикацию не менять.
