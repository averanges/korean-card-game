# Render connectivity probe — результат подготовки

Дата: 20.10.2026. Ветка: `multiplayer`. Развёртывание Render **не выполнялось**. Коммит и push не выполнялись. Существующие файлы игры/Worker/Pages не изменены: добавлены только `render-probe/`, корневой `render.yaml` и эта папка отчётов.

## Проверено локально

- Установка из lockfile командой `npm ci --omit=dev` успешна. Одна runtime-зависимость: `ws` 8.22.0.
- 4/4 серверных теста: HTTP/статические файлы/CORS/отсутствие игрового API; WS ready/pong и новое соединение; неверный путь/сообщение; различие идентификаторов двух процессов.
- 4/4 браузерных сценария Chrome: настоящий HTTP и четыре WS pong в течение 30 секунд; HTML вместо JSON и некорректное WS-сообщение; запрет URL комнаты в поле адреса; локальный `file:` HTML со скриптом, подключающийся к настоящему локальному серверу через HTTP и WS.
- Страница проверена при ширине 390 px: горизонтального переполнения нет. Скриншот `local-diagnostics-mobile.png` осмотрен.
- Синтаксическая проверка обоих JavaScript-файлов успешна.
- Локальный runtime: Node.js 24.19.0; Render настроен на 22.x. Запуск именно на Node 22 и создание сервиса на Render ещё не выполнены. Предупреждение npm об отличии локальной версии ожидаемо. Применяются стандартные API, доступные в Node 22, но это не подменяет будущую проверку на хостинге.

Машинный результат: `local-checks.json`. Все его адреса — localhost; поле «Корея» выбрано в автоматическом UI-тесте, **не является подтверждённым региональным измерением Render**. RTT в этом файле — локальные, не международные.

`diagnostics-offline.zip` содержит только `diagnostics.html` и `diagnostics.js` без зависимостей. Распаковать оба файла вместе; открыть HTML, ввести будущий адрес Render.

## Не проверено до разрешённой публикации

Фактическая доступность `onrender.com` из России/Кореи, TLS и прокси Render, региональные задержки, реальное засыпание и холодный старт, изменение процесса на Render. Реального URL сервиса пока нет. Ни локальные тесты, ни документация не доказывают отсутствие блокировок в конкретной сети.

Инструкция публикации, матрица региональных проверок, ограничения Free и условный план переноса существующих комнат находятся в `render-probe/README.md`. Следующий шаг — отдельное разрешение на публикацию тестового сервиса и затем JSON-отчёты из обеих стран. До этого рекомендация заменять рабочий Worker не сделана.
