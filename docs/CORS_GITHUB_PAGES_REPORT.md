# Мультиплеер GitHub Pages: CORS и сетевые ошибки

20 октября 2026. Ветка `multiplayer`. Изменения подготовлены локально; push, commit, deploy и изменение удалённых настроек не выполнялись.

## Причина, подтверждённая на опубликованном Worker

Отправлен только читающий `OPTIONS /api/rooms` на `https://hangul-durak-rooms.nick-belichenko.workers.dev` с `Origin`, `Access-Control-Request-Method: POST`, `Access-Control-Request-Headers: content-type`.

| Origin | Ответ сейчас | Access-Control-Allow-Origin |
|---|---:|---|
| `https://averanges.github.io` | **403** | отсутствует |
| `https://hangul-durak.netlify.app` | **403** | отсутствует |
| `https://korean-card-game-multiplayer.pages.dev` | 204 | тот же Origin |
| `http://localhost:5173` | 204 | тот же Origin |
| `https://not-allowed.example` | 403 | отсутствует |

Также настоящим Chrome открыт опубликованный GitHub Pages, выполнен переход в мультиплеер и попытка создания комнаты. Воспроизведено **`Failed to fetch`**; комната не создалась. Тело запросов, секреты и WebSocket-фреймы не записывались. Ответ браузерного preflight не попал в события Playwright; HTTP 403 подтверждён отдельными OPTIONS-запросами выше.

Это установленная проблема опубликованной конфигурации доступа: GitHub Origin не разрешён. Браузер не может прочитать такой отказ CORS как обычный JSON `origin_forbidden`, поэтому показывает общий сетевой сбой. Префикс `/korean-card-game/` не входит в Origin и не должен добавляться в список.

`signal aborted without reason` — другая форма исходного исключения при отмене запроса. На клиенте уже был таймер 12 секунд с `AbortController.abort()`, а UI показывал `error.message` без нормализации. По одному этому сообщению нельзя доказать, что российский сбой вызван только CORS: запрос/preflight мог также зависнуть из-за доставки до Worker. Доступность статического GitHub Pages не гарантирует доступность домена `workers.dev` из той же сети. Проверки из России в этой среде не выполнялись.

## Подготовленное исправление

### Worker configuration

В `worker/wrangler.jsonc` к прежнему `ALLOWED_ORIGINS` добавлены:

```text
https://hangul-durak.netlify.app
https://averanges.github.io
```

Три прежних значения сохранены без изменений:

```text
https://korean-card-game-multiplayer.pages.dev
http://localhost:5173
http://127.0.0.1:5173
```

`FRONTEND_ORIGIN`, имя Worker, Durable Object namespace, миграции, TTL и остальные настройки не менялись. Если в удалённой панели есть дополнительные разрешённые домены, их нужно сохранить при применении: **добавлять новые значения к текущему списку, не заменять неизвестную удалённую конфигурацию вслепую**. Административный полный список удалённых переменных не считывался.

Код `worker/src/index.ts` уже корректно проверяет точное совпадение Origin до REST и WebSocket. Для разрешённых источников OPTIONS возвращает 204 и нужные заголовки. Реальные ответы, включая ошибки 400/401/404/409, получают CORS-заголовки. Для чужих Origin сохраняется отказ 403 без разрешения чтения. Дефекта в этом коде не обнаружено, поэтому серверную реализацию и протокол не переписывали. Wildcard `*` и разрешение всех `github.io`/`netlify.app` не добавлялись.

Ожидаемый успешный preflight после применения конфигурации:

```text
HTTP 204
Access-Control-Allow-Origin: https://averanges.github.io
Access-Control-Allow-Methods: POST, GET, OPTIONS
Access-Control-Allow-Headers: Content-Type
Vary: Origin
```

### Client transport

В `src/rooms/connection.ts` добавлен общий ограниченный по времени `postRoom` для создания, входа и ручного восстановления:

- При сетевом сбое — понятное сообщение о недоступности сервера, возможной сетевой проблеме или CORS. Точная причина не выдумывается.
- При отмене собственным 12-секундным таймером — «Сервер комнат не ответил за 12 секунд…». Проверяется состояние `AbortSignal`, а не зависящий от браузера текст ошибки.
- Таймер охватывает также чтение тела после получения заголовков.
- HTML/некорректный JSON — сообщение о некорректном ответе, без вывода тела.
- Структурированные отказы сервера (`room_full`, `unauthorized` и другие) продолжают обрабатываться прежним `RoomAccessError`.
- Таймер очищается. Автоматических повторов POST нет. `credentials: omit`, форматы запросов, сохранение секретов, проверки ответов, авторизация и логика WebSocket не менялись.

Используется прежняя область ошибки в RoomLobby/восстановлении. Компоновка UI не менялась; изменён только необходимый текст сетевых ошибок. Исключения, URL с приватными данными, запросы и секреты не выводятся в новый интерфейс.

## Проверки

- **92 общих теста прошли**, включая пять новых проверок транспорта: `Failed to fetch` без утечки контрольной строки, отмена без причины, тайм-аут тела ответа, некорректный JSON/сохранение серверного отказа, очистка таймера и отсутствие повторов.
- **39 серверных тестов прошли**. Новые тесты используют настоящий Miniflare/Worker/Durable Objects и список из изменённого `wrangler.jsonc`:
  - все пять разрешённых Origin получают preflight 204;
  - Origin с путём, похожий домен, другой `github.io`, `null` и отсутствие Origin отклоняются;
  - настоящий POST создаёт комнату (201), второй игрок входит (200), повторный вход с прежним joinKey не занимает новое место;
  - восстановление проверяет секрет; третий игрок/неверный секрет/неверный запрос отклоняются с читаемыми CORS-ответами для разрешённого Origin;
  - WebSocket от GitHub получает 101, но доступ к месту по-прежнему требует правильный секрет. Чужой Origin не получает upgrade.
- **4 браузерные проверки production UI прошли**: сетевой отказ, тайм-аут, HTML вместо JSON, занятая комната. Проверено возвращение кнопки в доступное состояние и ровно один POST. Эти отрицательные ответы моделировались локально в браузере; успешные запросы/WS проверены настоящим локальным Worker выше.
- TypeScript frontend/Worker — успешно. Обычная production-сборка и сборка GitHub Pages с production endpoint — успешно. Статическая проверка всех 17 файлов JS/CSS/WebP/SVG для GitHub Pages прошла.
- Положительная проверка создания/входа на **опубликованном** Worker пока не может пройти: удалённая конфигурация намеренно не обновлялась и всё ещё отклоняет GitHub Origin.

Общие тесты в среде Codex запускались прежним `work/check-rooms.mjs solo` через Node test runner из-за ранее установленной ошибки окружения `tsx`; исходный набор не сокращался. Серверные — штатным `worker/scripts/test.mjs`.

## Что необходимо применить после подтверждения

1. На существующем Worker проверить текущее значение `ALLOWED_ORIGINS` и **добавить** GitHub/Netlify, сохранив все прежние разрешённые источники. Изменение локального файла само по себе опубликованный Worker не исправляет. Применение через настройки Cloudflare либо согласованный deploy требуется отдельно; агентом оно не выполнено.
2. Обновить frontend GitHub Pages, чтобы пользователи получили новые понятные сообщения. Для самого разрешения CORS важно прежде всего изменение Worker configuration; одна публикация frontend не исправит серверный preflight 403.
3. Не менять `FRONTEND_ORIGIN` ради добавления CORS: клиент GitHub Pages уже строит приглашение со своим `/korean-card-game/`.

## Проверка в реальных браузерах после применения

В Корее и России открыть `https://averanges.github.io/korean-card-game/`, перейти в мультиплеер. В Network проверить:

1. `OPTIONS /api/rooms`: 204, точный разрешённый Origin без пути.
2. `POST /api/rooms`: 201. Скопированная клиентом ссылка остаётся под `/korean-card-game/room/ID`.
3. Во втором браузере/телефоне открыть ссылку: preflight для join успешен, `POST .../join` — 200.
4. WebSocket — 101, оба игрока видны. Обновление вкладки восстанавливает прежнее место, а не создаёт новую раздачу.
5. Старые Cloudflare Pages и Netlify, а также локальная разработка продолжают подключаться.
6. При временном отключении сети не теряется секрет; после возврата проверить прежнее восстановление соединения.

Обычное открытие Worker в адресной строке без Origin может дать 403 по существующей политике — это не равнозначно недоступности API из разрешённой игры.

Если в России после успешного исправления CORS остаётся 12-секундный тайм-аут, прислать только статус/длительность OPTIONS и POST, сообщение интерфейса, браузер, сеть и наличие VPN. Проверить другую сеть. Не присылать HAR, тело запроса с joinKey, ответ с recoverySecret, персональный код или WebSocket-фреймы. Тайм-аут после разрешения Origin требует отдельной проверки доступности именно `workers.dev`, а не только GitHub Pages.

Основание проверки заголовков: [официальный пример CORS Cloudflare Workers](https://developers.cloudflare.com/workers/examples/cors-header-proxy/).
