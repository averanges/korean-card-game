# Hangul Durak — перенос транспорта на Node.js / Render

Дата проверки: 20.10.2026. Ветка `multiplayer`. Статус: **играбельный локальный прототип готов к пробной публикации по отдельному разрешению**. Commit, push, deploy, изменение repository variables и переключение рабочего GitHub Pages не выполнены. Опубликованный Render пока остаётся прежним connectivity probe.

## Реализация

| Часть | Решение |
| --- | --- |
| Правила, магия, замки, награды, словари | Прямое использование существующих модулей без изменения игровой логики |
| Модель мест, секреты, восстановление | `worker/src/model.ts` без изменений |
| Команды, игровые снимки и события | `worker/src/gameSession.ts` и `magicSession.ts` без изменений |
| Протокол клиента | Существующий `src/rooms/protocol.ts`, version 1 |
| HTTP адаптер | `server/src/input.ts`, `server.ts`: прежние create/join/recover, схемы, проверки и CORS |
| Сериализация/сокеты | `server/src/room.ts`: очередь на комнату, авторизация, heartbeat, receipts, ревизии, замена сокета, TTL |
| Хранение | `Map` одного процесса; никакого обещания восстановления после его гибели |
| Render диагностика | Сохранены `/health`, `/diagnostics.html`, `/diagnostics.js`, тестовый `/ws`; health дополнен `mode:rooms-memory` |
| Клиент | `readiness.ts` плюс адаптация connection/lobby/recovery и текста статуса NetworkTable |
| Переключение Pages | Workflow читает публичную repository variable API с прежним Cloudflare fallback; base path прежний |

Cloudflare Worker, Durable Objects, протокол, существующее браузерное хранение recoverySecret/joinKey, игровой движок, словари, TTS и анимации не изменены. Исходники Worker импортируются как общая серверная логика; зависимость `cloudflare:workers` на Node не загружается. Изменения `NetworkTable` касаются только текста состояния связи.

Новые файлы: `server/` (исходники, сборщик, lockfile, примеры окружения, инструкция и тесты), `src/rooms/readiness.ts`, `src/roomReadiness.test.ts`, `scripts/check-render-browser.mjs`, `scripts/check-render-wake.mjs`, эта папка отчёта/скриншотов. Изменены: `src/rooms/connection.ts`, `RoomLobby.tsx`, `RecoveryAccess.tsx`, `NetworkTable.tsx`, `src/roomTransport.test.ts`, `render.yaml`, `.github/workflows/deploy-pages.yml`, `scripts/check-pages-build.mjs` и `.gitignore` (исключён тестовый build сервера). Прежний `docs/render-probe/published-check.json` оставлен как существующий посторонний незакоммиченный результат; он не изменялся.

## Автоматические проверки

**Node transport: 9/9 интеграционных тестов.** Настоящий HTTP listener на loopback и настоящие TCP WebSocket `ws`; ответы сервера не подменяются.

1. Полная обычная партия до совпадающего результата у обоих игроков: атака, защита, подкидывание, взятие и завершение раунда/партии.
2. Полная партия с замками: первое открытие, правильные ответы, закрытие задания, восстановление открытого вопроса после смены соединения и окончательный результат. Магические награды выдаются существующим движком.
3. Все семь видов магии: Mirror, Chance, Fate с восстановлением выбора цели, Ghost, Gift, Hat, Monkey; повтор ACK, скрытые задания, blind refs, сохранение попыток после переподключения и сгорание после трёх неверных ответов.
4. HTTP `/health`, диагностические файлы, CORS/preflight, валидация схем/колоды, ограничение тела, третье место и повтор по чужому имени.
5. Неверный recoverySecret по REST/WS и запрещённый Origin по HTTP/WS.
6. Refresh-подобное новое соединение и временный обрыв сохраняют руки, стол, ревизию и receipt. Новый авторизованный сокет вытесняет старый ровно по прежней политике; проигравшая вкладка получает 4009.
7. Ограничения незавершённой авторизации, rate limit, oversized payload и запрет снимка до авторизации.
8. Два конкурирующих join занимают только одно оставшееся место; два конкурирующих хода с одной ревизией не применяются оба; подмена player/лишние поля отклоняются.
9. Истечение TTL закрывает сокеты; новый процесс **не восстанавливает** комнату старого процесса. Этот отрицательный тест фиксирует ограничение памяти.

Для быстрого покрытия всех видов магии один тест использует детерминированную начальную раздачу. Она внедряется только в отдельное `server/.test-build` во время компиляции теста. В исходниках, production `dist`, HTTP endpoints и конфигурации runtime такого режима нет. Остальные полные партии используют настоящую случайную раздачу. Production и тестовые артефакты разделены.

**Клиент/движок: 98/98 тестов.** Включают 5 новых проверок readiness и проверку отмены HTTP при уходе из формы: готовность, отсутствие зависимости `/health` у прежнего Worker, 90-секундный timeout с отменой, HTTP refusal/cancel и безопасный повтор 503 GET. Существующие тесты восстановления, TTS, скрытых карт, правил/инверсии, учебных счётчиков и одиночного режима прошли. В ограниченной среде выполняется тот же набор исходных `src/*.test.ts` после временной компиляции, через Node test runner.

**Прежний Cloudflare runtime: 39/39 тестов**, в том числе Miniflare HTTP/WS и восстановление Durable Objects. Worker исходники и настройки не изменялись.

TypeScript frontend и Node adapter: успешно. Production-сборка сервера: успешно. `npm run build` frontend: успешно. Pages-проверка JS/CSS/WebP/SVG и 404 fallback: 17 ресурсов, корректный `/korean-card-game/`.

Локальный runtime тестов — Node 24.19.0; Render-конфигурация — Node 22, применяются API, доступные в Node 22. Проверка именно новой Node-серверной версии на Render и региональная игра ещё не выполнены.

## Настоящее приложение в Chrome

`browser-checks.json`: production frontend под `/korean-card-game/` и реальный локальный Node backend, два независимых браузерных хранилища. Проверены:

- Создание комнаты формой, вход второго участника по ссылке, начало игры.
- Мобильные 390×844 и 360×780: выбор карты, атака, выбор допустимой цели и защита, завершение раунда.
- Прямой deep link и refresh получают настоящий HTTP 404 с Pages fallback body; React запускается, ресурсы загружаются, место/стол восстанавливаются. Это поведение существующего GitHub Pages fallback, а не серверный SPA rewrite.
- Принудительный обрыв настоящего браузерного WebSocket: автоматическое новое соединение без перезагрузки, прежняя ревизия восстановлена.
- Offline/online и reload, отсутствие JavaScript ошибок.
- Одиночный стол по `/singleplayer` продолжает запускаться независимо от Node backend.

Скриншоты: `node-network-390-attack.png`, `node-network-360-defense.png`. UI/дизайн игры не перерабатывались.

`wake-checks.json`: отображение прошедших секунд и успешное создание комнаты после задержанного настоящего `/health`; timeout 90 секунд без POST и с доступной повторной попыткой; отдельное HTTP 403 сообщение и отмена при уходе из формы без запоздалого создания комнаты. В этих отрицательных/временных сценариях задержка/отказ health моделируются браузером; это **не измерение реального Render cold start**. Игровые серверные снимки не подменяются. `wake-stage-390.png` показывает реальный этап ожидания.

## Ограничения и следующий шаг

Память сохраняется только до остановки процесса. После сна/redeploy/сбоя комнаты, задания, эффекты и receipts теряются; секрет сам по себе не восстановит их. Frontend это явно сообщает. Не добавлены БД, файловое сохранение, репликация, autoscaling, перенос активных DO-комнат или производственные нагрузочные гарантии. Ограничение в 100 комнат/1000 сокетов — защитный предел прототипа, не измеренная пропускная способность.

Готовность: **да для пробной реальной партии после разрешённого deploy и переключения сборки**, нет для долговечной production-эксплуатации. Доступность нового Node-сервера из России/Кореи и настоящий cold start проверяются после публикации. Успех прежнего connectivity probe не заменяет проверку игры.

Порядок публикации и отката подробно описан в `server/README.md`: обновить настройки существующего тестового Render-сервиса (Root Directory — корень репозитория), вручную развернуть Node backend, проверить health mode/CORS/двух игроков, только затем задать repository variables API и пересобрать Pages. Приглашение остаётся `https://averanges.github.io/korean-card-game/room/ID`; оба игрока должны открыть новую сборку и новую комнату. Worker остаётся доступным для отката.
