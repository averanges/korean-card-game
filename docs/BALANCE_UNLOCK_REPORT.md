# Баланс наград и раскрытие учебного замка

20 октября 2026. Ветка `multiplayer`. Commit, push и deploy не выполнялись.

## Изменения

- `src/learning.ts`: вероятность замка — **60%**, вероятность награды — **50%**. Добавлен `learning.rewardMisses`, отдельная пара счётчиков игроков. После двух первых открытий физических карт без награды следующее первое открытие гарантирует одну карту из оставшегося пула. Фактическое получение награды обнуляет счётчик. Ошибки, повторные ответы, повторная блокировка и передача уже открытой физической карты не увеличивают его и не дают повторных наград. При пустом пуле награды не создаются; счётчик насыщается на двух.
- Счётчик входит в прежнее сохраняемое состояние игры: в сети — транзакция Durable Object, в одиночной игре — существующее локальное сохранение. Общий редьюсер используется обоими игроками и ботом. В старых сохранениях без этого поля отсчёт начинается с нуля при первом новом учитываемом открытии. Старую историю неудачных проверок задним числом не восстанавливаем.
- `src/GameAnimationLayer.tsx`, `src/learning.css`: только эффект открытия обычной карты — золотая вспышка замка, исчезновение красной обложки с цепями, короткое расхождение световых фрагментов цепей, свечение рамки. Продолжительность **1 секунда**. Эффект накладывается на реальную открытую карту, учитывает её наклон и размеры. Дополнительная движущаяся копия обычной карты не создаётся; перелёта в центр и подъёма нет. Слой пропускает нажатия, состояние игры применяется сразу. При уменьшении движения — непосредственное раскрытие карты.
- `src/OrdinaryHand.tsx`, `src/MobileHand.tsx`, `src/mobile/MobileFan.tsx`: безопасные DOM-маркеры уже открытых собственных карт для привязки эффекта в настольной руке, мобильном веере и обзоре. Закрытые и слепые карты не получают физические ID через эти маркеры.
- `src/UnlockDialog.tsx`: учебное окно вынесено в портал, чтобы мобильный обзор руки не перекрывал варианты ответа. Эффект раскрытия также использует портал поверх обзора. Эта проблема была обнаружена автоматической проверкой настоящих нажатий.

Согласно последнему уточнению, последовательность, тайминги и оформление **получения магической награды не переделывались**, включая легендарные карты. Веса редкости, магические эффекты, аудирование, серверные команды и правила Дурака не изменены. Для баланса не понадобились новые команды, поля проекции или отдельная серверная реализация.

## Проверки

- **86 общих тестов — успешно.** Проверены границы новых вероятностей, гарантия на третьем открытии, обычное случайное получение до гарантии, сброс, независимость игроков, ошибки без продвижения счётчика, повторная блокировка/передача карты, исчерпание пула, сериализация, refresh одиночной партии и бот.
- **36 серверных тестов — успешно.** Дополнительно проверены сохранение счётчика через сериализацию комнаты и восстановление снимка, награда после двух восстановленных промахов, атомарность и отклонение повторного ответа. Сохранены прежние тесты WebSocket, приватности, магии и восстановления.
- TypeScript frontend и Worker — успешно; `npm run build` — успешно. Проверки мобильной и учебной production-сборки — успешно.
- Playwright проверил production-приложение с подготовленным **реальным игровым состоянием**, созданным общим движком через добор. Ответ отправлялся кнопкой приложения. Проверены веер 390 px, desktop 1440 px, расширенный обзор 390 px и системное уменьшение движения. Геометрия и transform эффекта неизменны на 270/700/900 мс; длительность 1 секунда; `pointer-events: none`; движущейся копии обычной карты нет. Сетевые гарантии проверены серверными тестами, а не подменой сетевых снимков в браузере.
- Дополнительно эффект был проверен при естественном доборе в одиночной мобильной партии. Полный случайный прогон до всех трёх компоновок не использован как критерий готовности; повторяемая визуальная проверка описана выше.

Тестовые изменения: `src/learning.test.ts`, `src/soloSession.test.ts`, `worker/test/learningSession.test.ts`, `worker/test/magicSession.test.ts` (обновлена прежняя проверка вероятности).

Новый воспроизводимый UI-чекер: `scripts/check-unlock-effect.mjs`. Требует production preview по `http://127.0.0.1:4176` и скомпилированные модули после серверных тестов. `PLAYWRIGHT_MODULE` и `CHECK_BROWSER` позволяют указать установленный Playwright и Chrome. Проверка работает только с локальным адресом.

В среде Codex общие тесты запускались через существующий игнорируемый `work/check-rooms.mjs solo` (тот же набор исходных тестов, Node test runner), серверные — через штатный `worker/scripts/test.mjs`. Причина обходного запуска общих тестов — ранее установленная ошибка окружения `tsx / uv_os_get_passwd ENOMEM`. Сборка выполнялась штатной командой проекта.
